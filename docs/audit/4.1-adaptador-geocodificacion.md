## 1. Implementación

Se creó `servicio-geocodificacion` con Spring Boot 4.0.8, Java 21 y `RestClient`. El servicio expone `POST /v1/geocodificaciones` y consulta Nominatim o el stub de WireMock mediante un cliente aislado.

Componentes principales:

- `NominatimConfig` configura la URL base, timeouts y el encabezado `User-Agent`.
- `NominatimClient` encapsula la llamada HTTP a `/search`.
- `GeocodificacionService` resuelve coordenadas externas y aplica fallback manual.
- Resilience4j protege la llamada con un Circuit Breaker llamado `nominatim`.
- `GeocodificacionExceptionHandler` devuelve respuestas RFC 7807 con correlación.
- `GeocodificacionApiClient` integra el adaptador con `servicio-operaciones-partidos`.
- `SedeService` geocodifica antes de persistir y no guarda sedes cuando la resolución falla.

## 2. Contratos y reglas verificadas

- Dirección resuelta por Nominatim/WireMock: se retornan latitud y longitud oficiales.
- Proveedor caído o circuito abierto, sin coordenadas manuales: geocodificación devuelve `503 Service Unavailable`.
- Dirección sin resultados: geocodificación devuelve `422 Unprocessable Entity`.
- Proveedor caído con coordenadas manuales: se utiliza el fallback manual.
- En `servicio-operaciones-partidos`, la caída del servicio externo se expone como `502 Bad Gateway` y una dirección no encontrada conserva el `422`.
- Una sede solo se persiste después de obtener coordenadas válidas.

## 3. WireMock y configuración

Se mantuvo el stub genérico de Nominatim para las pruebas normales y se agregó `wiremock/mappings/nominatim-no-results.json`, que devuelve `[]` para `Calle Inexistente 9999, Ciudad Desconocida, Argentina`.

La URL de WireMock permanece como configuración predeterminada en `application.yml`; la URL real de Nominatim queda comentada para que el equipo pueda alternarlas sin variables de entorno de IntelliJ.

## 4. Evidencia de pruebas

- Alta de sede con geocodificación automática: `201`, coordenadas del stub y persistencia SQL confirmada.
- Alta con coordenadas manuales y proveedor disponible: `201`; se mantienen las coordenadas externas según la política actual.
- Coordenadas manuales incompletas: `400`; no se persiste la sede.
- Dirección sin resultados mediante stub vacío: `422`; no se persiste la sede.
- Mapeo de estados HTTP verificado en cliente y controlador: `422` (Dirección no encontrada), `503` (Geocodificación no disponible en adaptador) y `502` (Bad Gateway en operaciones ante indisponibilidad o fallo de conexión).
- WireMock detenido sin coordenadas manuales: `502` desde operaciones; no se persiste la sede.
- WireMock detenido con coordenadas manuales: `201`; se persisten las coordenadas manuales.
- Compilación y suite de pruebas de `servicio-geocodificacion`: `BUILD SUCCESS` (7 tests ejecutados y aprobados).

## 5. Decisiones para la defensa

- Se usa `RestClient` dentro de un cliente dedicado para aislar la comunicación externa.
- Se diferencia una dirección no encontrada (`422`) de una indisponibilidad del proveedor (`503`).
- El Circuit Breaker evita insistir contra un proveedor caído.
- Las coordenadas manuales funcionan como fallback de contingencia, no como reemplazo prioritario cuando Nominatim responde correctamente.
- La sede se persiste después de la geocodificación para evitar registros incompletos.
