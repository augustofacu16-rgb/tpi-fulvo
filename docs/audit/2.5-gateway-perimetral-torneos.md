#### 1. ¿Qué y Cómo se hizo?
* **Componentes / Módulos intervenidos:** `api-gateway` operando en la rama de trabajo aislada `feature/2.5-gateway-perimetral-torneos`.
* **Archivos creados o modificados:**
  - `api-gateway/src/main/java/com/fulvo/gateway/config/GatewayRoutesConfig.java`: Configuración programática de rutas de Spring Cloud Gateway con `RouteLocatorBuilder` (Apunte 19). Se introdujo una ruta de alta prioridad para los subrecursos de torneos delegados al microservicio de operaciones (`/v1/torneos/*/partidos/**`, `/v1/torneos/*/posiciones/**`, `/v1/torneos/*/goleadores/**` hacia el puerto interno 8082), evitando que la ruta comodín de torneos (`/v1/torneos/**` hacia el puerto 8081) intercepte indebidamente las consultas operativas.
  - `api-gateway/src/main/java/com/fulvo/gateway/config/SecurityConfig.java`: Configuración reactiva perimetral `@EnableWebFluxSecurity` con `SecurityWebFilterChain` (Apuntes 20 y 21). Se fijaron las reglas canónicas de control de acceso basado en roles (RBAC):
    - `POST /v1/torneos`: Exclusivo `ROL_ORGANIZADOR` (bloqueo con 403 Forbidden ante cualquier otro rol y 401 Unauthorized para anónimos).
    - `PATCH /v1/torneos/*/estado`: Exclusivo `ROL_ORGANIZADOR` (cierre o cancelación).
    - `POST /v1/torneos/*/fixtures`: Exclusivo `ROL_ORGANIZADOR` (generación algorítmica).
    - `POST /v1/torneos/*/solicitudes-inscripcion`: Exclusivo `ROL_FANATICO` (postulación de equipo y plantel de buena fe).
    - `PATCH /v1/solicitudes-inscripcion/*/admision`: Exclusivo `ROL_ORGANIZADOR` (aceptación/rechazo).
    - `GET /v1/torneos/*/solicitudes-inscripcion/**`: Exclusivo `ROL_ORGANIZADOR` (inspección organizativa).
    - `DELETE /v1/torneos/*/equipos/*`: Permitido a `ROL_ORGANIZADOR` y `ROL_DELEGADO`.
    - `POST /v1/equipos/*/reemplazos-jugadores`: Exclusivo `ROL_DELEGADO`.
    - `GET /v1/**`: Permitido a cualquier usuario autenticado.
    - Integración perimetral de los manejadores `GatewayAuthenticationEntryPoint` y `GatewayAccessDeniedHandler`.
  - `api-gateway/src/main/java/com/fulvo/gateway/security/GatewayAuthenticationEntryPoint.java`: Implementación reactiva de `ServerAuthenticationEntryPoint` para peticiones anónimas (HTTP 401 Unauthorized), respondiendo bajo el estándar RFC 7807 (`application/problem+json`) con detalle, timestamp y propagación del encabezado `X-Correlation-ID`.
  - `api-gateway/src/main/java/com/fulvo/gateway/security/GatewayAccessDeniedHandler.java`: Implementación reactiva de `ServerAccessDeniedHandler` para peticiones con privilegios insuficientes (HTTP 403 Forbidden), respondiendo bajo el estándar RFC 7807 (`application/problem+json`) con detalle descriptivo y correlación de trazabilidad.
  - `docs/agentes/TASKS.md`: Marcadas como completadas las tareas 2.5.1 y 2.5.2.

* **Endpoints y Contratos implementados / asegurados:**
  - `POST /v1/torneos`: Requiere `ROL_ORGANIZADOR`. Si el solicitante posee `ROL_FANATICO`, `ROL_DELEGADO` o `ROL_ARBITRO`, el Gateway interrumpe la petición perimetralmente con HTTP 403 Forbidden y payload RFC 7807 sin tocar los microservicios de backend. Sin token Bearer responde HTTP 401 Unauthorized.
  - `POST /v1/torneos/{id}/solicitudes-inscripcion`: Requiere `ROL_FANATICO`.
  - `PATCH /v1/solicitudes-inscripcion/{id}/admision`: Requiere `ROL_ORGANIZADOR`.
  - `GET /v1/torneos/**`: Accesible para cualquier rol autenticado.
  - `GET /v1/torneos/{id}/partidos`, `GET /v1/torneos/{id}/posiciones`, `GET /v1/torneos/{id}/goleadores`: Enrutados con precedencia hacia `servicio-operaciones-partidos:8082`.

* **Lógica técnica y de dominio aplicada:**
  - Aislamiento perimetral reactivo no bloqueante (Spring Cloud Gateway / WebFlux sobre Netty).
  - Inspección sin estado de tokens JWT emitidos por Keycloak a través de `KeycloakReactiveRoleConverter`.
  - Estandarización de errores perimetrales reactivos bajo RFC 7807 (`ProblemDetail`), asegurando uniformidad total con los manejadores `@RestControllerAdvice` de los microservicios servlet downstream.

#### 2. ¿Qué hubo que arreglar sobre la marcha?
* **Problemas técnicos encontrados:**
  1. Al intentar usar `ObjectMapper` en los manejadores de seguridad reactiva, la compilación falló debido a que `jackson-databind` no formaba parte del classpath de compilación directo de `api-gateway` (gestionado de forma transitiva o mínima por Netty/WebFlux). Un intento de incorporar `spring-boot-starter-json` requirió resolución de dependencias externas bloqueada por el entorno cerrado de compilación.
  2. Enrutamiento ambiguo de subrecursos: los endpoints operativos asociados al torneo (`/v1/torneos/{id}/partidos`, `/v1/torneos/{id}/posiciones`, `/v1/torneos/{id}/goleadores`) habrían sido consumidos por el comodín `/v1/torneos/**` de `servicio-torneos` si no se separaban las rutas en Gateway.
* **Soluciones y Workarounds aplicados:**
  1. Se implementó la serialización JSON del `ProblemDetail` de forma nativa e inmutable utilizando bloques de texto de Java 21 (`""" ... """.formatted(...)`), evitando dependencias pesadas innecesarias y garantizando tiempo de compilación cero (`BUILD SUCCESS` en 7 segundos) y formato RFC 7807 estricto.
  2. Se reordenaron las definiciones del `RouteLocator` registrando primero la ruta `servicio-operaciones-torneos-subrecursos-route` con las rutas específicas hacia el microservicio de operaciones, asegurando la precedencia de evaluación de predicados de Spring Cloud Gateway.

#### 3. ¿En qué difiere con lo establecido en el Plan Original?
* **Modificaciones del Modelo de Datos / Entidades:** Ninguna (módulo perimetral de enrutamiento y seguridad).
* **Ajustes en Funcionalidades o Reglas:** Se refinó la regla de `POST /v1/torneos/*/solicitudes-inscripcion` para restringirla explícitamente a `ROL_FANATICO` (en lugar de `.authenticated()` general), alineándose de forma estricta con la especificación FN-04 y RN-03 del cuestionario aprobado.
* **Motivo del cambio:** Cumplimiento riguroso de las reglas de admisión y separación de roles requeridas por la cátedra.
