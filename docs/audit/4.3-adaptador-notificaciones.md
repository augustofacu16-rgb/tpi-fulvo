#### 1. ¿Qué y Cómo se hizo?
* **Componentes / Módulos intervenidos:**
  - `servicio-notificaciones`: microservicio adaptador desacoplado de notificaciones transaccionales por correo electrónico hacia Mailpit (:1025).
* **Archivos creados o modificados:**
  - `servicio-notificaciones/pom.xml`: proyecto Spring Boot 4.0.8 / Java 21 con `spring-boot-starter-web`, `spring-boot-starter-mail`, `spring-boot-starter-validation`, `spring-boot-starter-actuator`, `lombok`, `fulvo-common-lib` y `springdoc-openapi-starter-webmvc-ui` (3.0.2).
  - `servicio-notificaciones/src/main/resources/application.yml`: configuración de puerto `8083`, `spring.mail.host` (`${MAIL_HOST:localhost}`), `spring.mail.port` (`${MAIL_PORT:1025}`), timeouts SMTP, `app.mail.from` / `app.mail.from-name`, Actuator `/health-check` y patrón de log con `[%X{correlationId}]`.
  - `servicio-notificaciones/src/main/java/com/fulvo/notificaciones/ServicioNotificacionesApplication.java`: clase de arranque Spring Boot.
  - `servicio-notificaciones/src/main/java/com/fulvo/notificaciones/config/OpenApiConfig.java`: configuración de OpenAPI 3.0 y Swagger UI para el servicio.
  - `servicio-notificaciones/src/main/java/com/fulvo/notificaciones/service/EmailSenderService.java`: servicio encargado de construir mensajes MIME HTML con `JavaMailSender` y `MimeMessageHelper` (UTF-8), con captura silenciosa de excepciones SMTP (`try-catch`) retornando `boolean` para preservar la transacción del llamador (RN-12).
  - `servicio-notificaciones/src/main/java/com/fulvo/notificaciones/controller/NotificacionEmailController.java`: controlador REST `POST /v1/notificaciones/emails` con validación `@Valid` sobre `NotificacionEmailDTO`, anotaciones OpenAPI (`@Tag`, `@Operation`, `@ApiResponses`) y respuesta `202 Accepted`.
* **Endpoints y Contratos implementados:**
  - `POST /v1/notificaciones/emails`: recibe `NotificacionEmailDTO` (`destinatario`, `asunto`, `cuerpo`, `tipoEvento`, `fechaHora`), responde `202 Accepted` con `{mensaje, tipoEvento, destinatario, enviado}` o `400 Bad Request` (RFC 7807 `ProblemDetail`) ante errores de validación.
  - `GET /health-check`: estado de salud incluyendo componente `mail` (`localhost:1025`).
  - `GET /v3/api-docs` y `/swagger-ui.html`: contrato OpenAPI 3.0.
* **Lógica técnica y de dominio aplicada:**
  - El scaffolding base había sido adelantado en la Subsección 2.4 (`AUDIT-20261110-24`). En 4.3 se completó la externalización del remitente (`app.mail.from` y `app.mail.from-name`), la documentación OpenAPI 3.0 con `springdoc-openapi-starter-webmvc-ui` (`OpenApiConfig` y anotaciones en el controlador) y la verificación integral de contratos y resiliencia contra Mailpit.
  - Auto-configuración de `fulvo-common-lib` (`CorrelationIdFilter` y `GlobalExceptionHandler` RFC 7807) verificada en runtime.

#### 2. ¿Qué hubo que arreglar sobre la marcha?
* **Problemas técnicos encontrados:** Ninguno bloqueante; el módulo base ya compilaba desde el adelanto de 2.4.
* **Soluciones y Workarounds aplicados:**
  - Se externalizaron `app.mail.from` y `app.mail.from-name` en `application.yml` con valores por defecto para evitar datos fijos en código Java.
  - Se añadió `springdoc-openapi-starter-webmvc-ui` (3.0.2) y `OpenApiConfig` para alinear el adaptador con el estándar OpenAPI del resto del ecosistema (Subsección 2.6 / Etapa 5).

#### 3. ¿En qué difiere con lo establecido en el Plan Original?
* **Modificaciones del Modelo de Datos / Entidades:** Ninguna; `servicio-notificaciones` es un adaptador stateless sin base de datos propia.
* **Ajustes en Funcionalidades o Reglas:** El endpoint `POST /v1/notificaciones/emails` devuelve `202 Accepted` con el campo booleano `enviado` indicando si el despacho SMTP a Mailpit tuvo éxito o si fue contenido silenciosamente por contingencia.
* **Motivo del cambio:** Permite que tanto los llamadores asíncronos (`servicio-torneos` con `@Async`) como las pruebas de verificación observen el resultado sin romper la resiliencia ni propagar errores 500.

#### 4. Puntos Clave para la Defensa Oral (Coloquio con Docentes)
* **Decisiones de diseño a defender:**
  - **Desacoplamiento por Microservicio Adaptador:** Aislar `JavaMailSender` y la configuración SMTP en `servicio-notificaciones` evita acoplar `servicio-torneos` y `servicio-operaciones-partidos` al protocolo de correo.
  - **Resiliencia Operativa (RN-12):** La captura silenciosa de excepciones SMTP (`MailException` / `Exception`) con logging en `EmailSenderService` asegura que una caída de Mailpit nunca aborte una inscripción, admisión o suspensión de partido.
  - **Contrato Común y RFC 7807:** Reutilización de `NotificacionEmailDTO`, `GlobalExceptionHandler` y `CorrelationIdFilter` desde `fulvo-common-lib`.
* **Preguntas probables de los profesores:**
  - *¿Qué pasa si Mailpit está caído cuando se envía una notificación?* `EmailSenderService` captura la excepción, registra el error en el log con `correlationId` en el MDC y retorna `false`; el controlador responde `202 Accepted` sin propagar `500` ni revertir la transacción del servicio llamador.
  - *¿Por qué `spring.mail.host` usa `${MAIL_HOST:localhost}`?* Para funcionar localmente contra `localhost:1025` durante desarrollo y cambiar a `mailpit` dentro de la red Docker `bda-net` mediante variable de entorno sin recompilar.
