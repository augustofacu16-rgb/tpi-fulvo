#### 2. ¿Qué hubo que arreglar sobre la marcha?
* **Problemas técnicos encontrados:** Se duplicó la declaración del logger al conservar un campo manual junto con `@Slf4j`; se retiró el campo manual. La ejecución inicial de SQL falló por un espacio previo a `psql`; se corrigió ejecutando el comando en una sola línea. El script Docker de inicialización no se reejecuta automáticamente sobre un volumen ya inicializado.
* **Soluciones y Workarounds aplicados:** Se aplicó `initdb/init-schemas.sql` mediante `docker compose exec -T postgres-db psql -U postgres -d fulvo_db -v ON_ERROR_STOP=1 --single-transaction < initdb/init-schemas.sql`. La revisión previa del agente ejecutó `mvn -o -B compile -DskipTests` con `BUILD SUCCESS`; las pruebas funcionales posteriores fueron realizadas por Santiago.
* **Pendiente de validación compartida:** El DTO todavía no rechaza campos obligatorios ausentes antes de persistir. Debe coordinarse con Luis Miguel la validación del contrato común y comprobar que este lote inválido devuelva HTTP 400 con errores de cliente adecuados, conservando el rollback. El log del fallo no fue aportado, por lo que no se certifica aquí la excepción concreta que produjo el 500.

#### 3. ¿En qué difiere con lo establecido en el Plan Original?
* **Modificaciones del Modelo de Datos / Entidades:** Las entidades iniciales están en `com.fulvo.operaciones.models`. El modelo actual incorpora los campos iniciales del fixture; sede, árbitro, goles, penales y ganador aún no están modelados en `Partido`.
* **Ajustes en Funcionalidades o Reglas:** Los campos opcionales `sedeId` y `arbitroDni` del DTO no son trasladados por el mapeo actual. No se certifica su integración ni el fixture completo entre microservicios. Repetir una petición crea filas adicionales; no se implementó deduplicación.
* **Motivo del cambio:** Desarrollo incremental de la persistencia del lote, previo al modelado operativo completo. La recepción y persistencia básica, así como el rollback del escenario probado, tienen evidencia positiva; la subsección queda en observación por las limitaciones detalladas. No se declara superado ningún Gate.
