#### 2. ¿Qué hubo que arreglar sobre la marcha?

- PostgreSQL estaba detenido: el fallo JDBC impedía iniciar Operaciones. Se indicó
  levantar la infraestructura y comprobar su estado; no se agregó un dialecto para
  ocultar la falta de conexión.
- Docker requería JARs previamente empaquetados y no publica los puertos internos
  de los servicios. Se aclaró el acceso por Gateway y la necesidad de generar el
  JAR y reconstruir la imagen para mostrar las anotaciones nuevas.
- Swagger devolvía 401 desde el contenedor aunque el código actual permite sus
  rutas. Tras indicar regenerar el JAR e imagen del Gateway, Santiago confirmó
  que podía acceder y visualizar la documentación.
- Se documentó el comportamiento observado en el código, evitando prometer 404
  en estadísticas sin registros o respaldo manual si Geocodificación está caído.

#### 3. ¿En qué difiere del plan original?

Se amplió la cobertura explícita a scheduler, reprogramaciones y recepción de lotes
para cubrir el 100 % de los endpoints de negocio presentes. No se modificaron
entidades, persistencia, validaciones de ejecución ni reglas de negocio. Se reutilizó
bearerAuth de la configuración existente y CrucePartidoDTO de la librería compartida.

No se cierra 5.5/5.6 ni se certifica la etapa 5 por completar estas anotaciones.
Los límites actuales de los servicios (sincronización HTTP, respaldos y consultas
sin validación de existencia) se exponen en el contrato en lugar de modificarse.

#### 4. Puntos clave para la defensa oral

- OpenAPI describe el contrato; las anotaciones de seguridad no ejecutan autorización.
  Spring Security valida JWT, Gateway controla roles y Operaciones verifica el árbitro.
- Schema documenta campos; Bean Validation y el dominio siguen aplicando las reglas.
- Los códigos 422/502 se documentan según lo que responde Operaciones, no según
  el código de error original del proveedor externo.
- Un 202 del lote se devuelve tras persistir, mientras que un 200 del scheduler
  no garantiza que todas sus consultas remotas hayan sido exitosas.
- Swagger sirve para inspeccionar y ejecutar el contrato; la certificación E2E
  de los escenarios oficiales requiere las tareas específicas de 5.5 y 5.6.
