# [AUDIT-20261114-STATE] Patrón State de Partido

- Fecha: 2026-11-14.
- Estado: IMPLEMENTADO Y VERIFICADO.
- Rama: refactoring/subseccion-3.
- Complementa las refactorizaciones previas de dominio; no certifica Gate 2B.

## Implementación

Partido delega iniciar, cancelarPorIncidentes, validarFinalizacion, finalizar, incorporarClasificado y resolverAvanceSinRival en EstadoDelPartido.

EstadoDelPartido implementa State con comportamientos inmutables y compartidos:
- Programado: inicio y recepción/resolución técnica de clasificados.
- EnCurso: validación de resultado, finalización por acta y cancelación arbitral.
- Reprogramado: recepción/resolución técnica de clasificados, manteniendo la regla anterior que rechaza inicio directo.
- SinOperaciones: comportamiento de rechazo compartido por FINALIZADO, CANCELADO y SUSPENDIDO para las operaciones actuales. No se considera SUSPENDIDO un estado terminal del negocio: sus futuras operaciones deberán implementarse cuando corresponda.

ReceptorDeClasificados comparte el comportamiento de PROGRAMADO/REPROGRAMADO. Las operaciones no permitidas se rechazan por defecto con las mismas excepciones y mensajes anteriores. El único switch selecciona el objeto State a partir del enum; las decisiones por operación se resuelven mediante polimorfismo.

Las reglas independientes del estado (participantes, formato, penales, marcador y ganador) permanecen encapsuladas en Partido. Las acciones internas de transición tienen acceso de paquete para los objetos State, y no son API pública de controladores/servicios. Se deshabilitó el setter público de estado para que los consumidores utilicen las operaciones del dominio.

## Persistencia y API

Se conserva EstadoPartido como enum con @Enumerated(EnumType.STRING) en la misma columna. No se agrega una columna ni una entidad State. El comportamiento se obtiene del enum al ejecutar cada operación; no se almacena un segundo estado que pudiera quedar desincronizado durante la hidratación JPA.

Los objetos State no contienen datos mutables del partido y se pueden compartir. JPA mantiene acceso por campos y no requiere un setter de estado. Endpoints, DTOs HTTP, transacciones y verificaciones JWT conservan sus contratos.

## Defensa

El enum representa el estado persistido. El objeto State determina qué comportamiento está disponible. Partido conserva sus invariantes y el servicio coordina autenticación, repositorios, transacciones, bracket y otros microservicios. Se mantienen las reglas existentes: State no introduce nuevas transiciones.
